# 左联知识库大创项目完整实施方案

## 1. 项目定位

本项目不是单纯的数据展示网站，也不是面向课堂使用的教学产品。项目定位为：

> 以可追溯历史证据为基础，研究左联人物、组织、事件与社会关系网络，并通过数字人文知识库完成研究验证、成果展示和答辩演示。

项目同时服务两类成果：

1. **研究成果**：可复核的数据、证据链、质量评估和网络分析结论。
2. **答辩成果**：可操作的知识库、可解释的图表、清晰的方法与局限说明。

## 2. 总体完成标准

结项时必须满足以下条件：

- 每个核心研究结论都能回溯到具体事实和来源。
- 事实、线索、推断和争议不会在展示层混为一谈。
- 数据生成与发布流程能够从脚本重复执行。
- 数据质量有量化报告，不用“数据很多”代替质量证明。
- 至少形成 3 个有证据支撑的研究发现。
- 答辩演示能够在 5 分钟内展示“问题、方法、发现、价值、局限”。

## 3. 数据架构

### 3.1 原始资料层

保留 Excel、OCR 文本、日记、研究论著和网页来源，不直接作为展示真值。

### 3.2 研究证据层

以实体表、关系表和 `fact_evidences.csv` 为主真值，保留：

- 支持与反向证据
- 来源等级
- 具体定位与摘录
- 审核状态
- 候选和争议结论

### 3.3 展示发布层

由研究证据层自动生成，只展示符合发布规则的数据，并明确标记置信度和审核状态。

## 4. 六阶段路线图

| 阶段 | 核心问题 | 主要产物 | 完成指标 |
| --- | --- | --- | --- |
| Phase 1 | 谁可以被称为左联正式成员 | 组织身份台账和分层结论 | 全部结论有证据；正式成员满足判定规则 |
| Phase 2 | 每条重要事实依据是什么 | 通用事实证据表和覆盖率报告 | 核心事实具备可定位证据或被标记待核 |
| Phase 3 | 研究数据如何安全发布 | 研究层到展示层生成器 | 展示层不把候选与争议写成确定事实 |
| Phase 4 | 事件和地点是否足够准确 | 事件、地点质量报告和修订数据 | 模糊事件与坐标精度均可量化 |
| Phase 5 | 4238 条人物关系是否可信 | 分层抽样审计和错误分析 | 完成约 400 条关系人工审计 |
| Phase 6 | 知识库能得出什么研究发现 | 网络分析、研究报告、答辩资产 | 至少 3 项可复核发现和完整答辩链路 |

## 5. Phase 1：组织身份重建

### 已交付

- `org_membership_evidences.csv`
- 证据驱动的 `org_memberships.csv`
- 组织身份判定脚本、Schema、测试和前端分层展示

### 当前结果

- 45 名已确认正式成员
- 77 名候选人物
- 28 名相关人物
- 581 条组织身份依据

### 阶段边界

该结果是自动证据提取与规则判定结果。后续可以人工复核，但不得退回角色字段自动确认的旧逻辑。

## 6. Phase 2：通用事实级证据层

### 目标

把“实体引用过哪些来源”升级为“某条具体事实由什么来源支持”。

### 实施范围

第一批覆盖：

- 组织身份结论
- 事件存在与事件日期
- 人物生卒年
- 人物角色

第二批再覆盖人物关系和地点事实。

### 交付物

- `data/processed/fact_evidences.csv`
- `research/analysis/build_fact_evidences.py`
- `research/analysis/report_evidence_coverage.py`
- `research/drafts/reports/phase2_evidence_coverage_report.md`
- Schema、测试与 README 说明

### 验收指标

- 每条事实证据拥有唯一 ID、主体、谓词、来源、定位、摘录和审核状态。
- 所有正式组织成员结论可映射到事实证据。
- 有明确事件证据的事件可映射到事实证据。
- 缺少可定位摘录的核心事实被明确列入待核队列。
- Schema 0 严重错误，测试和静态构建通过。

## 7. Phase 3：研究层与展示层分离

### 目标

展示页面不直接读取研究主表，而由可审计规则生成发布数据。

### 发布规则

- `confirmed`：默认展示。
- `related`：展示并标记“相关”。
- `candidate`：默认隐藏，可在研究模式查看。
- `disputed`：仅在争议视图展示，必须同时显示争议说明。
- 缺少来源或存在严重 Schema 错误的数据不得发布。

### 交付物

- `research/analysis/build_publish_data.py`
- `data/publish/` 发布数据目录
- `data/publish/publish_manifest.json`
- 发布规则测试
- 前端“公开模式 / 研究模式”切换
- `phase3_publish_gate_report.md`

### 验收指标

- 展示层完全由脚本生成。
- 发布清单记录生成时间、输入快照、过滤数量和原因。
- 候选与争议事实不存在确定性文案。
- 删除发布目录后可一条命令完整重建。

## 8. Phase 4：事件与地点质量治理

### 目标

解决事件定义模糊、日期精度混乱和地点坐标看似精确但实际不精确的问题。

### 事件治理

- 定义 `specific_event`、`activity_lead`、`aggregate_event`。
- 对低置信度和 `needs_manual_review=yes` 事件建立审核队列。
- 检查事件名称、日期、参与者、地点和证据的一致性。

### 地点治理

- 新增 `coordinate_precision`：`exact`、`street`、`district`、`city`、`unknown`。
- 新增 `geocoding_method` 和 `coordinate_note`。
- 城市中心坐标不得显示为精确旧址。

### 交付物

- 事件与地点审核脚本
- 审核队列和质量报告
- 地图精度可视化

### 验收指标

- 所有事件具备事件类型。
- 所有坐标具备精度说明。
- 城市级坐标在前端使用不同符号或范围表达。
- 低置信度记录均进入可追踪审核队列。

## 9. Phase 5：人物关系抽样审计

### 目标

用统计抽样回答“人物关系数据有多可信”，而不是依靠个别示例。

### 抽样方法

按以下维度分层抽取约 400 条：

- 关系类型
- 风险等级
- 来源等级
- 置信度
- 是否涉及高中心性人物

### 人工审核字段

- `audit_decision`：正确、部分正确、错误、无法判断
- `error_type`：人物错配、关系类型错误、语境不足、证据不支持、重复等
- `auditor_note`

### 交付物

- 固定随机种子的抽样脚本
- 审核工作表
- 统计汇总脚本
- 关系质量审计报告

### 验收指标

- 抽样过程可重复。
- 总体与分层准确率、错误率可计算。
- 错误类型能转化为后续数据修订规则。
- 报告明确说明样本量与推断局限。

## 10. Phase 6：研究分析与答辩交付

### 研究问题

优先回答以下三类问题：

1. 左联人物网络中哪些人物承担跨群体连接作用？
2. 不同时间阶段的人物关系结构如何变化？
3. 正式成员、相关人物和候选人物在网络位置上有何差异？

### 分析方法

- 度中心性、中介中心性和特征向量中心性
- 社群发现
- 时间切片网络
- 组织身份分层比较
- 证据等级敏感性分析

### 交付物

- 可重复分析脚本
- 图表与图表说明
- 研究发现报告
- 数据质量与局限报告
- 答辩 PPT 大纲与演示脚本
- 现场演示检查清单

### 验收指标

- 至少 3 项研究发现，每项都可追溯到数据和证据。
- 分析明确区分“数据观察”与“历史解释”。
- 答辩演示包含质量控制和局限，不夸大结论。
- 所有图表可由脚本重新生成。

## 11. 质量门禁

每阶段结束必须运行：

```powershell
python -m pytest -v
python -c "from kb_schema import validate_data_dir; r=validate_data_dir('data/processed'); print(len(r.errors), len(r.warnings))"
python build_static_site.py
```

新增或修改的脚本还必须通过定向 `ruff` 检查。全仓历史 lint 债务单独记录，不在阶段任务中无边界清理。

## 12. 项目风险与控制

| 风险 | 控制措施 |
| --- | --- |
| OCR 文字误识别 | 保存原文定位，自动提取结果标注审核状态 |
| 百科被当成权威证据 | 百科仅作为 D 级线索 |
| 网络图把数量误当价值 | 研究发现必须经过证据等级敏感性分析 |
| 候选结论被误展示 | 研究层与发布层分离 |
| 人工审核不可重复 | 固定抽样规则、记录审核决定和说明 |
| 答辩夸大结论 | 单独提供局限说明与口径清单 |
